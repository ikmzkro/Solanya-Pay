# Coding rules

- One function, one responsibility
- Consider splitting a function once it exceeds 50 lines
- Never swallow errors (no empty catch blocks), and include try/catch in callers too
- TDD: write tests before implementing

# Working style

- Ask questions and confirm before implementing
- Keep changes small and ask for a review each time
- **Stay strictly within the requested scope.** If asked for "just the first step" or "just one endpoint", do not implement the whole related flow. If unsure, confirm before starting.
